# 周报生成器

用 Q助理扫码登录 → 获取 QFlow 本周工作内容 → 一键生成周报 → 存入本地指定目录。

## 快速开始

### 方式一：本地直接打开（最简单）

```powershell
cd weekly-report
python -m http.server 8899
```

然后浏览器打开 <http://127.0.0.1:8899/>

> 必须用 **Chrome 或 Edge**（目录选择 API 仅 Chromium 支持）。

### 方式二：部署到网站

整个 `weekly-report/` 目录就是**纯静态文件**，无需后端、无需构建。把它传到任意静态托管即可：

- 公司内网 Nginx：拷贝到站点根目录
- GitHub Pages / Vercel / Netlify：直接指向该目录
- 对象存储（OSS/COS）+ CDN：上传全部文件

> ⚠️ 由于要调用 Q助理接口，部署后需确保**浏览器能访问** `client.qzhuli.com` 与 `qflow.qzhuli.cn`（内网部署时注意网络策略）。

## 使用步骤

## 界面

工作台式布局：**左侧操作栏 + 右侧主区**，白色底 + 天空蓝主题。

**设计取向：Apple 排版纪律 + Meta 色彩自信**

| 取自 | 做法 |
|---|---|
| **Apple** | 大字级跳跃（12 → 42px）、紧字距（`-0.03em`）、慷慨留白、**去卡片边框**（靠背景色差 + 发丝线）、克制的阴影 |
| **Meta** | **近纯黑正文**（`#0a0a0a`）、饱和天空蓝（仅主操作与选中态）、鲜明状态色、等宽数字 |

| 区域 | 内容 |
|---|---|
| 顶栏 | 品牌、东八区实时时钟、登录状态胶囊（毛玻璃） |
| 左栏 | 扫码登录 / 统计窗口 / 运行日志（段间发丝线分隔，无卡片框） |
| 主区指标条 | 本周有进展（42px 主指标）/ 其中已完成 / 当前积压 / 数据源 |
| 主区列表 | 本周需求，**按「项目 · 板块」分组**，状态用彩色圆点 |
| 主区输出 | 文件名、保存目录、生成与保存、周报预览 |

### 字体

| 用途 | 方案 | 体积 |
|---|---|---|
| 西文 / 数字 | **自托管 Inter 变量字体**（`vendor/fonts/`） | 124 KB |
| 中文 | 系统字体链：`Noto Sans SC` → `苹方` → `微软雅黑` | 0 |

> 中文未自托管：完整中文字体约 17 MB，不适合随仓库分发。
> Inter 是公认的 SF Pro 最佳开源替代，能拿到 Apple 排版的骨架。

### 1. 登录

页面打开后自动显示二维码，用**手机上的 Q助理 App** 扫码。二维码 300 秒有效，过期可点「重新获取二维码」。

登录后自动换取 QFlow 令牌（2 小时有效）。

### 2. 获取本周工作内容

点「获取本周工作」。

- 默认统计窗口：**上周五 14:00 ~ 本周五 14:00**（与公司既有周报口径一致）
- 可点窗口面板右上角图标自定义起止时间
- 按阶段拉取**你参与过的**全部需求（含已完成），不是全公司数据

主区会显示指标条与需求列表，**默认全选**，可逐条取消或点「全选 / 全不选」。

### 3. 生成并保存

点「生成周报」→ 展开「周报预览」检查 → 点「保存到本地」。

**首次使用需选一次目录：**

1. **先在资源管理器里建好目标文件夹**（如 `D:\周报`）
2. 点「选择目录」→ 弹出系统窗口
3. 在窗口里**双击进入**那个文件夹（如 `D:\周报`），再点「选择文件夹」

> ⚠️ **不要停在磁盘根目录上确认**。Chrome 会拦截 `C:\`、`D:\` 这类盘符根目录，以及 `Windows`、`Program Files`、用户目录根部，报错「无法打开此文件夹，因为其中含有系统文件」。**必须选中一个具体的子文件夹**。
>
> 可用示例：`D:\周报`、`D:\工作\周报`、`C:\Users\<你>\Documents\周报`

选好后，授权会被记住，下次自动复用，无需重复选择。文件名可在保存前修改。

## 周报格式

```markdown
# 黄捷 · 周报（2026-10-09 ~ 2026-10-16）

> 窗口：**2026-10-09（周五） 14:00** ~ **2026-10-16（周五） 14:00** ｜ 本周 **6 条需求**有进展 ｜ 当前积压 **5 条**

## 本周情况

### Q助理

#### 文档编辑器

| NO. | 需求标题 | 动作 |
| --- | --- | --- |
| NO.774 | 聊天消息中的链接自动解析网页标题 | 提出需求、完善需求、提交审批 |

## 当前积压（未完成）

| NO. | 需求标题 | 状态和卡住时间 |
| --- | --- | --- |
| NO.602 | 私人助理新增AI主动工作能力：每日前瞻 | 完善中 · 卡住10天 |

## 下周计划

- （待补充）
```

- **本周情况**：只含**你本人**的动作，按 项目 → 板块 分组
- **当前积压**：当前负责人是你、且未完成的需求，含卡住天数
- **下周计划**：留空待补
- 板块归类沿用公司既有规则（`classify.py` 移植），与公司周报口径一致

## 常见问题

**Q：为什么只能选一个根目录，不能直接列盘符？**

浏览器安全模型不允许网页枚举磁盘或遍历整个文件系统（否则任何网站都能偷看你的硬盘）。所以需要你先授权一个根目录，之后就能在页面内逐层浏览。

**Q：Firefox / Safari 能用吗？**

能用，但不支持目录选择，会自动降级为「下载文件」。

**Q：显示「登录已过期」怎么办？**

重新扫码登录即可。QFlow 令牌 2 小时有效。

**Q：本周没有我的动作？**

页面会提示，仍可生成周报（内容为「本周无需求进展」）。

**Q：板块显示「通用/未分类」？**

说明该需求标题未命中现有归类规则。这是沿用公司既有规则的结果，如需调整可修改 `src/classify.js`。

## 技术说明

### 为什么不需要后端

已实测验证：

- `client.qzhuli.com` 返回 `Access-Control-Allow-Origin: *`
- `qflow.qzhuli.cn` 预检回显 Origin
- 浏览器可用 MD5（blueimp）与 Node 结果**逐字符一致**
- 纯浏览器全链路已跑通：签名 → SSO → QFlow 令牌 → 取数

因此所有请求都在**用户浏览器内**完成，服务器不接触任何凭据。

### 取数口径（重要）

**`requirement_user_filter=participated` 单独使用时，只返回"进行中"的需求，全部「已完成」会被排除。**

实测（2026-10-16）：

| 查询方式 | 条数 |
|---|---|
| `participated` 单独使用 | 19 条（仅进行中） |
| `participated` + 逐阶段拉取 | **87 条**（含已完成 55、已取消 13） |
| 其中我参与过的已完成 | 55 条 |

因此正确做法是 **`participated` + `progress_stage` 逐阶段拉取**（`src/qflow.js` 的 `fetchParticipated` 即如此）。

**已完成/已取消的需求同样计入周报** —— 验收完成代表工作量，不该被丢弃。

修复前本周窗口只统计到 6 条需求；修复后为 **16 条**（多出 8 条已完成、1 条已取消、1 条待审批）。

> 覆盖性交叉验证：独立全量扫描 1034 条已完成需求，找到我参与过的 55 条；
> 与 `participated + 已完成` 查询结果**完全吻合**，两种方法互相印证。

### 已知限制

1. **依赖 Q助理内部接口**：官方开放平台无 QFlow 数据能力，故走内部接口。Q助理改版可能失效，届时只需改 `src/qflow.js`。
2. **`participated` 只覆盖"当前仍参与"的需求**：若某需求本周操作过、事后被移出参与人，会漏掉（实测存在个别案例，如 NO.119）。
3. **积压口径**为"当前负责人是我"，非"所有我参与且未完成"。
4. **板块归类沿用公司规则**：未命中关键词的需求归为「通用/未分类」。
